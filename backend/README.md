# Resume ↔ JD Semantic Matcher — Backend

FastAPI backend for parsing resumes/job descriptions, extracting skills, and
computing a semantic match + skill gap report.

**No pretrained models are used anywhere.** Matching is powered by:
1. **TF-IDF** — fit live on each resume/JD pair at request time (classical
   statistical model, no external weights).
2. **Word2Vec** — trained *from scratch* by you, with `gensim`, on a bundled
   corpus (`scripts/generate_corpus.py`) that grows as real resumes/JDs are
   analyzed. Nothing is downloaded from the internet.

The final semantic score averages both signals, then blends with skill-gap
coverage for the overall match score.

## Setup

```bash
python -m venv venv
source venv/bin/activate        # Windows: venv\Scripts\activate
pip install -r requirements.txt

# 1. Generate the training corpus
python scripts/generate_corpus.py

# 2. Train the Word2Vec model from scratch (your own trained model)
python scripts/train_embeddings.py

# 3. Run the server
uvicorn app.main:app --reload --port 8000
```

API docs (Swagger UI): http://localhost:8000/docs

### Retraining as data accumulates
Every analyzed resume/JD is saved to `resume_matcher.db` (SQLite). Re-run
`python scripts/train_embeddings.py` any time to retrain Word2Vec on the
bundled corpus **plus** all accumulated real text — the model keeps
improving. This is what makes it "your own trained model," not a pretrained
one: you own the training data and the training run.

## API Contract (for the Next.js frontend)

Base URL (dev): `http://localhost:8000`

### `POST /api/analyze`
`multipart/form-data`. Provide resume + JD as EITHER a file or raw text:
- `resume_file` (file, optional) — .pdf/.docx/.txt
- `resume_text` (string, optional)
- `jd_file` (file, optional)
- `jd_text` (string, optional)

At least one of `resume_file`/`resume_text` and one of `jd_file`/`jd_text`
is required.

**Response:**

### `POST /api/parse`
`multipart/form-data`, field `file` (.pdf/.docx/.txt). Returns extracted text
— useful if the frontend wants to show/edit parsed text before analyzing.

### `GET /api/history?limit=20`
Returns recent analyses (id, timestamps, filenames — not full text).

### `GET /api/history/{id}`
Returns the full stored report for one past analysis.

### `GET /api/health`
Returns whether the Word2Vec model has been trained yet and its vocab size.

## Project structure
```
app/
  main.py                # FastAPI app, CORS, router registration
  routers/
    parse.py              # POST /api/parse
    analyze.py             # POST /api/analyze
    history.py             # GET /api/history[/id]
  services/
    parser.py              # PDF/DOCX/TXT -> clean text
    skill_extractor.py      # taxonomy-based skill matching
    matcher.py              # TF-IDF + self-trained Word2Vec similarity
    analyzer.py             # orchestrates gap analysis + scoring
  models/
    db.py                   # SQLite via SQLAlchemy
  data/
    skills_taxonomy.json    # curated skills list
    training_corpus.txt     # generated by scripts/generate_corpus.py
    word2vec.model           # generated by scripts/train_embeddings.py
scripts/
  generate_corpus.py        # builds the training corpus
  train_embeddings.py        # trains Word2Vec from scratch
```
